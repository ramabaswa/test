# NHI and Agent Access Management MVP Matrix

**Scope:** This matrix maps the NHI/AAM control plane implied by the security, deployment, and network architecture diagrams to the proposed MVP stack: **Microsoft Entra, Okta, Oasis Security, Azure APIM, Solo.io, ServiceNow, Microsoft Foundry, and Microsoft Agent 365**.

**Interpretation:**

- **In scope** — feasible for the MVP, using the named platform(s) and normal integration/configuration work.
- **Partial** — feasible only when the named platforms are integrated with an external control or when the capability is limited to a boundary rather than end-to-end.
- **Later** — valuable target-state capability that should not be a dependency for the initial MVP.
- **Out of scope** — not owned by this architecture layer or requires a specialized product/process beyond the MVP.

Reconcile discovered identities with Entra and the ServiceNow ownership record. |

| NHI authorization | Least-privilege scopes and tool entitlements | In scope | Entra + Solo | APIM, Foundry, Agent 365, Oasis | Entra grants downstream roles/scopes; Solo enforces MCP server, tool, and method permissions; APIM governs APIs; Foundry/Agent 365 constrain agent-connected tools. | NHI authorization | Delegated, on-behalf-of access | Partial | Entra | Foundry, Solo, APIM | Use delegated access only where a human/user context is required and supported. | AAM registration | Tool catalog and discovery control | In scope | Solo | ServiceNow, Agent 365, Entra | Solo provides protocol-aware tool discovery and exposure. | AAM registration | Model/provider allowlist | In scope | Foundry + Solo | APIM, ServiceNow | Foundry/application configuration defines approved models for hosted agents; Solo enforces approved provider/model access on governed AI traffic. | AAM runtime | Per-tool authorization | In scope | Solo + Entra | ServiceNow, Oasis | Enforce authorization at MCP method/tool invocation—not only at gateway entry. | AAM runtime | Per-step workflow policy | Partial | Foundry/application + Solo | Entra, APIM, ServiceNow | The agent framework must invoke policy for internal planning/state transitions; Solo/APIM enforce policy when a workflow crosses LLM, MCP, A2A, API, or network boundaries. ## MVP control-plane sequence

1. **Request and classify:** The requester submits an agent/MCP onboarding request in ServiceNow. The form captures use case, owner, environment, risk tier, data type, model/provider, proposed tools, and requested permissions.
2. **Provision a distinct NHI:** The onboarding service creates or associates an Entra workload/agent identity and writes its immutable identifiers to ServiceNow.
3. **Register approved runtime components:** Register the agent in Foundry and/or Agent 365, the MCP server/tools in Solo, and the service/API surface in APIM where conventional APIs are involved.
4. **Apply least privilege:** Assign Entra scopes/roles, APIM policy, Solo MCP/tool policy, allowed model/provider policy, private networking, and controlled egress.
5. **Validate NHI posture:** Oasis discovers/reconciles the NHI, credentials, permissions, ownership, relationship graph, and initial risk score.
6. **Operate and observe:** Foundry, Solo, APIM, Entra, and Azure/network logs emit correlated telemetry. ServiceNow owns exception, approval, and incident workflows.
7. **Contain and retire:** Risk events or lifecycle changes trigger revocation/rotation/removal across Entra, Key Vault, APIM, Solo, runtime registration, and network access; ServiceNow retains the evidence.

## MVP acceptance criteria

- Every onboarded agent has a **unique Entra identity**, named owners, environment, use case, risk tier, and ServiceNow record.
- Every MCP server and tool is **registered, versioned, approved, and discoverable only by authorized agents**.
- Agents obtain **short-lived, audience-scoped credentials**; no unapproved long-lived key is used in the primary path.
- An agent can invoke one approved tool but is denied a non-entitled tool at runtime, with evidence visible in audit logs.
- One high-impact tool action requires **ServiceNow human approval** bound to the exact requested action.
- Oasis identifies the agent/NHI, its credentials, effective permissions, owner, and blast radius; it opens or enriches a ServiceNow remediation task for a high-risk condition.
- A kill switch removes the agent's ability to invoke a tool within the agreed operational window.
- A single correlation identifier links the request, Entra identity, agent run, LLM/model activity, MCP call, downstream action, approval decision, and audit evidence.
